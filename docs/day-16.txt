1. OVERVIEW OF DAY 16 TASKS
----------------------------------------------------
Today's objective was to transition from individual pages to a cohesive Application Shell. We established the global navigation and layout system that defines the user experience of the FraudGuard terminal:
- Unified Layout System: Implemented a high-order `Layout` component using React Router's `<Outlet />` for efficient nested routing.
- Responsive Sidebar: Built a data-dense, professional sidebar with dynamic navigation items based on user roles.
- Global Header (Navbar): Created a persistent top-bar with context-aware titles and system notifications.
- Enhanced Routing: Migrated to a structured `/dashboard` architecture and enforced Role-Based Access Control (RBAC) at the component level.
- Premium UI Refinement: Applied Bloomberg-inspired dark aesthetics with subtle gradients, micro-animations (pulsing badges), and glassmorphism.

----------------------------------------------------
2. ARCHITECTURAL DECISIONS (INTERVIEW Q&A)
----------------------------------------------------

QUESTION: "Explain how your Layout system works in React."
ANSWER:
"I used a 'Wrapper Component' pattern with React Router's `<Outlet />`. Instead of repeating the Sidebar and Navbar on every page, I created a `Layout` component that acts as a shell. All protected routes are nested inside this Layout. The `<Outlet />` component then serves as a placeholder where the specific page (like Dashboard or Transaction Feed) is rendered. This ensures a consistent UI, improves maintainability, and prevents unnecessary re-renders of global components when navigating between pages."

QUESTION: "How did you handle responsiveness for a data-heavy enterprise dashboard?"
ANSWER:
"I implemented a 'Mobile-First Sidebar' strategy. On large screens, the sidebar is fixed and takes up 240px (`w-60`). On mobile, it's hidden behind a hamburger menu and uses a slide-in animation with a backdrop-blur overlay. I managed the sidebar's open/close state in the `Layout` component and passed it down via props. This ensures that the terminal remains usable even on tablets or phones during emergency fraud reviews."

QUESTION: "Why did you use NavLink instead of Link for navigation?"
ANSWER:
"I used `NavLink` from `react-router-dom` because it provides a built-in `isActive` state. This allowed me to apply specific styles—like the blue left border and the darker gradient background—automatically whenever the URL matches the nav item. This provides immediate visual feedback to the user about their current location in the application without needing to manually manage state for active links."

QUESTION: "How do you handle 'Admin Only' links in the sidebar?"
ANSWER:
"I implemented dynamic array filtering. Before rendering the navigation list, I check the user's role from the Redux state. If the user is an 'admin', I push the 'Admin Panel' item into the `navItems` array. This ensures that sensitive links aren't even present in the DOM for regular analysts, following the security principle of 'Defense in Depth' where the UI reflects the permissions of the backend."

----------------------------------------------------
3. TECHNICAL IMPLEMENTATION DEPTH
----------------------------------------------------

A. THE OUTLET PATTERN:
By wrapping routes in a Layout, we achieve a flat structure in the UI code while maintaining a nested structure in the router:
```jsx
<Route element={<Layout />}>
  <Route path="/dashboard" element={<Dashboard />} />
</Route>
```

B. ROLE-BASED SIDEBAR:
The sidebar logic is strictly decoupled. It doesn't just hide the link; it prevents the route from being accessible via the `ProtectedRoute` component which checks for `allowedRoles`.

C. MICRO-ANIMATIONS & UX:
- Pulse Badge: The Review Queue features a pulsing red badge to indicate urgency for pending transactions.
- Transition Durations: Used `duration-150` for hover effects to ensure the interface feels snappy and professional, avoiding the 'sluggish' feel of longer transitions.
- Z-Index Management: Carefully managed `z-index` (z-50 for sidebar, z-40 for overlay, z-30 for navbar) to ensure no visual overlaps during mobile interactions.
