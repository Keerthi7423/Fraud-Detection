====================================================
  FRAUDGUARD — DAY 9: GEMINI AI INTEGRATION
====================================================

In Day 9, we focused on the AI Scoring Service. This service is the "brain" of FraudGuard. It uses Google's Gemini AI to analyze transactions and determine if they are fraudulent or clean.

----------------------------------------------------
1. WHAT WE BUILT TODAY
----------------------------------------------------

A. AI Scoring Service Initialization:
   - Created the folder structure for the 4th microservice.
   - Installed core dependencies: 
     - @google/generative-ai (The Gemini SDK)
     - express, mongoose, dotenv (Standard microservice stack)
     - @aws-sdk/client-sqs (To communicate with other services later)

B. Gemini AI Integration:
   - Created `geminiClient.js`: Configures the connection to Google's Gemini 1.5 Flash model.
   - Created `aiScoringService.js`: This contains the core logic for prompting the AI.
     - PROMPT ENGINEERING: We created a specific prompt that tells the AI to act as a "bank fraud detection system" and return data in a strict JSON format.
     - DATA MAPPING: We mapped the AI's response (riskScore, riskLevel, reasons) into our system's format.

C. Robust Error Handling:
   - We implemented a fallback mechanism. If the AI service is down or the API key is invalid, the system returns a "safe" default (score 0, low risk) instead of crashing the entire pipeline.

D. Standalone Test Suite:
   - Created `test-gemini.js` to verify that the scoring logic works without needing the full microservices cluster running.

----------------------------------------------------
2. ARCHITECTURAL DECISIONS (Interview Gold)
----------------------------------------------------

Q: Why use Gemini 1.5 Flash?
A: Flash is optimized for speed and efficiency. In a fraud detection system, latency is critical. We need a model that can process a transaction in under 2 seconds. It's also free-tier friendly, making it perfect for development.

Q: Why separate AI scoring into its own service?
A: AI processing is "compute-heavy" and slow compared to database operations. By putting it in its own service:
   - We can scale it independently (run 10 AI containers and only 1 Auth container).
   - If the AI service crashes, users can still create transactions (they just won't be scored immediately).

Q: Why use Prompt Engineering instead of a traditional if/else model?
A: Traditional models are hard-coded. An LLM like Gemini can understand "context." It knows that a 2 AM transaction at a "Petrol Pump" in "Dubai" for someone living in "Mumbai" is highly suspicious, even without us writing a specific rule for it.

----------------------------------------------------
3. STEP-BY-STEP IMPLEMENTATION GUIDE
----------------------------------------------------

1. Setup: `npm install @google/generative-ai`
2. Config: Initialize `GoogleGenerativeAI` with your API key from Google AI Studio.
3. Prompting: Send the transaction details (Amount, Merchant, Location, Time) to the model.
4. Parsing: The model returns text; we use `JSON.parse()` to turn it into a JavaScript object.
5. Fallback: Wrap everything in a `try/catch` to ensure the system is "fault-tolerant."

----------------------------------------------------
4. INTERVIEW PREP: KEY QUESTIONS
----------------------------------------------------

Q1: What happens if the AI returns a wrong format?
A1: We use a "clean-up" step (regex to remove markdown fences) and a `try/catch` block. If `JSON.parse` fails, we default to a safe score. This is called "Graceful Degradation."

Q2: Is it safe to send transaction data to Gemini?
A2: For this project, we are using mock data. In a real bank (like JP Morgan), we would mask the data (replace "Keerthi" with "User_123") before sending it to a cloud AI to maintain PCI-DSS compliance.

Q3: How do you handle AI latency?
A3: This service is ASYNCHRONOUS. The Transaction Service puts the txn in a queue (SQS) and returns a "Success" to the user immediately. The AI Scoring Service picks it up from the queue whenever it's ready. The user never waits for the AI.
